# 阪東橋 3Dマップ（1.5km四方）

横浜市営地下鉄 阪東橋駅を中心にした、Webアプリ用の3Dマップ（GLB形式）です。
道路・白線・建物・地形などをパーツに分けて作ってあり、Blenderでも編集できます。

### 確認のしかた

- **公開ページで見る**：https://bandobashi-3dmap.pages.dev/ （スマホでも開けます）
- **手元で動かして見る**：`ビューアを開く.command` をダブルクリック → ブラウザで確認用ページ（viewer.html）が開きます（約13MB の読み込みに数秒）
  - 左のボタンで「真上・鳥瞰・駅前の車目線・交差点・首都高・京急の高架・丘の坂道」に移動
  - チェックボックスでパーツごとに表示／非表示。建物をクリックすると実測の高さと PLATEAU の建物ID が出ます
  - 見終わったら、開いた黒い画面（ターミナル）を閉じれば終了です
- **画像で見る**：`screenshots/` に上の7か所の画像があります（`screenshots/3km版/` は以前の3km四方版）

## 2. 作り方の検討：OpenStreetMap だけで作るか？

**結論：OpenStreetMap（OSM）を土台にしつつ、建物と地形は別のデータを使う「3つの組み合わせ」にしました。**

| パーツ | 使ったデータ | 理由 |
|---|---|---|
| 道路・車線・白線・横断歩道・線路・川・公園 | **OpenStreetMap** | 車線数・一方通行・橋/高架・横断歩道・信号の情報が入っている。範囲内の幹線道路108本のうち63本に車線数が登録されていた |
| 建物（約8,300棟） | **PLATEAU（国交省の3D都市モデル）横浜市 2024年度** | OSM の建物は約7,900棟あるが、**高さが入っている建物は0棟**。PLATEAU は航空測量で測った実際の高さが全棟にあり、一部（154棟）は屋根の形（LOD2）まである |
| 地形（土地の高低差） | **国土地理院の標高タイル（5mメッシュ）** | 範囲内は標高 約0m〜53m と起伏が大きい（南東と北西の丘）。平らな板にすると坂道や高架の高さが不自然になる |

### なぜ道路は PLATEAU ではなく OSM なのか

PLATEAU にも道路データはありますが、調べた結果、

- 阪東橋のまわりは「道路の面」だけ（LOD1）で、**車線の区別がない**
- 車線まで入っている（LOD3）のは関内駅周辺だけで、今回の範囲には入らない
- 白線（道路標示）のデータはどこにもない
- 首都高狩場線の高架は、阪東橋付近では入っていない可能性が高い（橋のデータがあるのは範囲の外の石川町・関内付近だけ）

ため、車線を再現するには OSM の「車線数・一方通行・橋」の情報から白線を組み立てるのが一番確実でした。

### 車線の再現方法（日本の標準的な決まりで組み立て）

- **車線の幅**：首都高 3.5m／国道・主要道 3.25m／その他 3.0m。OSM に幅が書かれていればそれを優先
- **左側通行**：上下2車線以上の道は、進行方向の左側に「上り」の車線を並べる
- **中央線**：片側2車線以上は黄色の実線、それ以外は白の実線
- **車線境界線**：白の破線（一般道 5m間隔、首都高 8m/12m）
- **外側線**：車道の両端に白の実線
- **横断歩道**：OSM の横断歩道の位置に、しま模様（幅45cm・間隔45cm）
- **停止線**：信号のある横断歩道の手前（車が来る側の車線だけ）
- **交差点**：白線は交差点の手前で止める。ただし、幹線道路が細い道と交わるところは幹線の線を途切れさせない（優先道路の扱い）
- **歩道**：主要な道路の両側に段差15cmで付ける。上下線が分かれている道路は外側（進行方向の左）だけ
- **高架・橋**：首都高狩場線・京急線の高架は、地上との接続点から坂の上限（道路6%・鉄道3.5%）を守って持ち上げ、桁と30m間隔の橋脚を付ける。川に架かる短い橋は両岸を水平につなぐ

> 右折専用レーンなどの「矢印」は、範囲内で OSM に登録があるのが1本だけだったため再現していません。

## 3. できあがったファイル

```
阪東橋3Dマップ/
├─ output/
│   ├─ glb/               … 元の精度の GLB（Blender に読み込む・加工する用）
│   ├─ glb_web/           … Web用の軽量版（中身は同じ。数値を圧縮して約27%軽く）
│   ├─ bandobashi_3dmap.blend … Blender のファイル（パーツごとにコレクション分け済み）
│   ├─ lanes.json         … 車線の中心線（アプリで車を走らせる用）
│   └─ buildings_index.json … 建物の一覧（PLATEAU の建物ID・高さ）
├─ viewer.html            … 表示確認用のビューア（three.js）
├─ site/                  … 公開用フォルダ（Cloudflare Pages にそのまま載せる。作り直す.sh が作る）
├─ 作り直す.sh            … 全部を作り直すスクリプト
├─ scripts/               … 変換プログラム
└─ data/                  … 元データ（OSM・標高・建物を変換したもの）
```

### GLB の中身（パーツ分け）

| ファイル | 中のパーツ（オブジェクト名） | 内容 |
|---|---|---|
| terrain.glb | `terrain` / `terrain_skirt` | 地形（10m間隔、公園などは緑色）／四辺の側面（不要なら隠す） |
| water.glb | `water` | 川・池の水面 |
| roads.glb | `road_surface` / `road_sidewalk` / `road_footpath` | 車道（アスファルト）／歩道（段差つき）／歩行者道・階段 |
| markings.glb | `marking_lane_white` / `marking_center_yellow` / `marking_crosswalk` / `marking_stopline` | 白線（外側線・車線境界）／黄色の中央線／横断歩道／停止線 |
| rail.glb | `rail_bed` / `rail_track` | 線路の道床／レール2本 |
| structures.glb | `structure_viaduct` | 高架の桁・橋脚 |
| buildings.glb | `building_53391520` など6個 | 建物（約1km四方の区画ごとに分割。壁と屋根で色分け） |
| bandobashi_all.glb | 上の全部 | 1ファイルにまとめたもの |

| | 三角形の数 | 元の精度 | Web用 | Web用を圧縮配信（gzip）したとき |
|---|---|---|---|---|
| 全部 | 約35万 | 17.5MB | 12.8MB | 約4.2MB |

### 座標の決まり

- **原点（0,0,0）＝阪東橋駅の位置・標高0m（東京湾の平均海面）**
- three.js（GLB）では **X＝東、Y＝上（標高 m）、Z＝南**。1単位＝1m
- Blender では X＝東、Y＝北、Z＝上
- 高さは実際の標高です。駅前は約2〜3m、丘の上は約50m

## 4. Webアプリでの使い方（three.js の例）

```js
import { GLTFLoader } from 'three/addons/loaders/GLTFLoader.js';
const loader = new GLTFLoader();
for (const name of ['terrain','water','roads','markings','rail','structures','buildings']) {
  loader.load(`glb_web/${name}.glb`, g => scene.add(g.scene));
}
// カメラの near は 0.5 以上にするか、renderer の logarithmicDepthBuffer: true を推奨
// （白線は車道から5cmだけ浮かせているため、遠くからだとちらつくことがある）
```

- Web用（glb_web）は「数値の圧縮（KHR_mesh_quantization）」だけを使っています。three.js の標準の読み込みでそのまま開けます（Draco などの追加の読み込み部品は不要）
- **車を走らせる**：`lanes.json` の `ways[].lane_paths[].path` が車線の中心線（[X, Y, Z] の点列、4m 間隔、道路表面の高さ）です。`dir` が `forward`（道の向きどおり）/`backward`（逆向き、点列は走る向きに並べ替え済み）。`from_node`/`to_node` は OSM の点の番号で、道どうしのつながりを作るのに使えます
- **建物をクリックして情報を出す**：建物の各頂点に `_BLDG`（建物の通し番号）を持たせています。three.js では `geometry.attributes._bldg` として読め、`buildings_index.json` の同じ番号から PLATEAU の建物ID・高さが分かります

## 5. Blender で編集するとき

- `output/bandobashi_3dmap.blend` を開くと、`01_terrain`〜`07_buildings` のコレクションに分かれています
- 建物は区画ごとに1つにまとめています。1棟ずつ分けたいときは、編集モードで「分離 → 構造的に分離していないパーツで」を使うと棟ごとに分かれます
- GLB を直接読み込む場合は `output/glb/`（元の精度）を使ってください

## 7. わかっている限界

| 内容 | 程度 | 対応案 |
|---|---|---|
| 車線数が OSM にない幹線道路（45本）は、道路の種類から標準値で補った | 見た目はそれらしいが実際と違う可能性 | 重要な道路だけ現地写真・航空写真で確認して `lanes` を追加 |
| 道幅は「車線数 × 標準の車線幅」で計算。実際の歩道幅・路肩とは数mずれることがある | 建物と道路の間に地面が見えることがある | PLATEAU の道路の面（LOD1）を使って幅を合わせることも可能 |
| 白線の約0.5%が、別の道路の帯の下に隠れる | 道路どうしが重なる所（高架の出入口や、斜めに交わる交差点など） | 必要なら手作業で修正 |
| 地形は 10m 間隔 | 細かい段差（擁壁など）はなだらかになる。道路の下は自動で地形を下げて、道路が地面に埋もれないようにしている（検査で埋もれ0件） | 5m 間隔にもできる（三角形が約4倍） |
| トンネル（首都高・地下鉄）は入れていない | 地下は表示しない | 必要なら別パーツで追加可能 |
| 右左折の矢印、ゼブラゾーン、バス停などの道路標示 | なし | OSM に情報がほぼないため |

## 8. 作り直す方法

```bash
./作り直す.sh
```

- `data/` にある元データから作り直します（Blender 4.5 を使用・約1分）。`data/` のファイルを消すと、その分だけ最新データをダウンロードし直します
- 範囲や中心を変えるときは `scripts/geo.py` の `LAT0, LON0, HALF` と `data/bbox.txt`・`data/plateau_bldg_urls.txt` を変更し、`data/` の3ファイル（osm_raw.json / dem.json / buildings.jsonl）を消してから実行します
- 作成日：2026-10-16（OSM は 2026-10-16 時点のデータ）
